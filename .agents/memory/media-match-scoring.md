---
name: Media match % scoring
description: How the feed "% match" badge is scored and calibrated (score-media-match edge fn)
---
- **Rule:** A numeric media match requires a concrete, signed user rating with a substantive relationship to the candidate. Exact canonical story identity is strongest, followed by franchise, creator, and conservative source-text semantic similarity. Generic audience, tone, style, pacing, or cross-format genre overlap cannot qualify a score.
- **Why:** coarse trait vocabularies made unrelated titles look alike and produced confident but indefensible matches.
- **How to apply:** An actual rating for the same title and format suppresses prediction. Weak or missing verified evidence returns no badge. Followed creators and explicitly taste-backed DNA may support an already-qualified rating but cannot create a score.
- **Rule:** Only authoritative or curated identities may receive exact-story weight. Title equality alone is never identity evidence. Provider identifiers may resolve through a trusted knowledge graph; an AI-proposed story label must not be treated as canonical identity.
- **Why:** Exact adaptation evidence is powerful enough that an unverified relationship would distort the percentage.
- **How to apply:** AI may classify bounded metadata or create embeddings only after a trusted provider record resolves. Caller fallback, failed lookups, and unsupported sources cannot qualify evidence. The deterministic scorer—not the model—chooses the percentage, and explanations cite the actual rated titles that contributed.
- **Rule:** Do not rank a small rating subset before fingerprints exist. Every addressable rating in the user's history must have a current fingerprint attempt before v3 finalizes a score; otherwise an older renamed adaptation can be excluded before its identity is known.
- **Why:** Pre-enrichment title/genre heuristics cannot discover authoritative story identity, creator, franchise, or semantic similarity and therefore create systematic false negatives.
- **How to apply:** Paginate the full rating history, reuse all fresh fingerprints, and continue cold per-user backfills in small fenced batches. Return pending between batches; only a zero-missing final recheck may release scoring.
- **Rule:** Moderate semantic similarity may qualify only for the same media format when multiple independent source-backed facets corroborate it (themes, tone, and style); it never crosses formats.
- **Why:** Real book-description embeddings cluster around lower cosine values than synthetic calibration pairs, while generic trait overlap alone still creates false positives.
- Keep v1 and v2 available for rollback and keep each scorer/fingerprint revision in an isolated cache namespace. Lease acquisition, completion, and release must remain atomically fenced so feed fan-out cannot duplicate score work or overwrite a newer result.
- **Deferred by user decision (Aug 2026): keep scoring personal-taste-only for now.** Inputs today: user's cross-media ratings, DNA profile, DNA signals + model's title knowledge. Deliberately NOT using community averages or taste-neighbor ("users like you") signals — too few real users; thin data would make scores feel random. **Revisit when many titles have ~5+ real-user ratings.** Agreed first step then: feed the title's Consumed avg/count + friends'/DNA-matches' ratings of that exact title into the prompt, adding guardrail cases before deploy. Full collaborative filtering only after real user growth.
- **Drift guardrail:** `node scripts/match-calibration-check.mjs` scores a fixed golden set against the real prompt (needs OPENAI_API_KEY). Run it after ANY prompt change, before deploying. Lessons baked in: gpt-4o-mini snaps to round band edges (40/70) without explicit numeric anchors + "pick a precise integer"; and it treats absence of genre kinship as a dislike unless told "absence of evidence is NOT a dislike" with a mixed-fit anchor.
